# fx-montecarlo

[![CI](https://github.com/SPA2006/fx-montecarlo/actions/workflows/ci.yml/badge.svg)](https://github.com/SPA2006/fx-montecarlo/actions/workflows/ci.yml)
[![Docs](https://github.com/SPA2006/fx-montecarlo/actions/workflows/docs.yml/badge.svg)](https://SPA2006.github.io/fx-montecarlo/)

**Documentation:** https://SPA2006.github.io/fx-montecarlo/

**Monte Carlo simulation of exchange rates** in C++20: scenario generation, risk of FX positions
(VaR, Expected Shortfall) and pricing of FX forwards and European FX options, validated against the
Garman–Kohlhagen closed form. This is the course project for "Software Engineering and C++ for
Quantitative Analysis and Algorithmic Trading" (topic: «Моделирование курса валют методом Монте-Карло»).

## What it does

An exchange rate *S* is quoted as units of domestic currency per one unit of foreign currency
(e.g. RUB per USD). The library simulates *S* along many random paths and turns the paths into
numbers a desk cares about.

**Models** (both simulated exactly, so the time step adds no discretisation bias):

| Model | Dynamics | Use |
|---|---|---|
| Garman–Kohlhagen (GBM) | dS = (r_d − r_f) S dt + σ S dW | risk-neutral pricing |
| Exponential Ornstein–Uhlenbeck | d ln S = κ(ln L − ln S) dt + σ dW | mean-reverting scenarios |

**Simulation:** any number of paths and time steps, reproducible by seed, optional
**antithetic variates** for variance reduction. Keep only terminal rates (O(paths) memory) or full
paths.

**Analytics:** mean, standard deviation, quantiles, **VaR** and **Expected Shortfall** of an FX
position, **Monte Carlo option prices with standard errors and 95% confidence intervals**, and the
Garman–Kohlhagen formula as the benchmark.

```cpp
#include "fxmc/pricing.hpp"
#include "fxmc/statistics.hpp"

fxmc::GbmModel model({/*spot*/ 100.0, /*r_d*/ 0.16, /*r_f*/ 0.04, /*sigma*/ 0.15});
fxmc::SimulationConfig cfg{/*paths*/ 200'000, /*steps*/ 252, /*horizon*/ 1.0,
                           /*seed*/ 42, /*antithetic*/ true};

auto terminal = fxmc::simulate_terminal(model, cfg);           // rates in 1 year
double forward = model.expected_rate(1.0);
auto pnl = fxmc::position_pnl(terminal, forward, -1'000'000.0); // 1M USD to pay, unhedged
double var99 = fxmc::value_at_risk(pnl, 0.99);

auto call = fxmc::mc_european_option(model, fxmc::OptionType::Call, 110.0, cfg);
// call.value ± 1.96 * call.std_error vs fxmc::garman_kohlhagen_price(...)
```

The demo uses illustrative parameters, not market data. GBM here is the risk-neutral model: its
drift is the interest-rate differential, not a forecast, so the demo measures FX risk against the
forward (the cost of staying unhedged). Real-world risk forecasts need a model calibrated to
history.

## Build

Requirements: CMake ≥ 3.20, a C++20 compiler (GCC ≥ 11, Clang ≥ 14, MSVC 2022), Git, and internet
access on first configure (GoogleTest and Google Benchmark are fetched automatically via
`FetchContent`).

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

Run the demo:

```bash
./build/fxmc_demo
```

## Tests

```bash
ctest --test-dir build --output-on-failure
```

Statistical tests use fixed seeds and tolerances of at least 4 standard errors, so they are
deterministic for a given standard library (verified identical with libstdc++ and libc++). The
closed form is checked against values computed independently with 30-digit arithmetic.

## Benchmark

```bash
./build/bench/fxmc_bench
```

Measured: terminal-rate simulation for 10k–1M paths, full paths with weekly and daily steps for both
models, and option pricing with 1M paths with and without antithetic variates (the standard error is
reported next to the time). CI runs the benchmark on every push and prints the results in the job
log and the run summary.

Build options: `-DFXMC_BUILD_TESTS=OFF`, `-DFXMC_BUILD_BENCHMARKS=OFF`.
